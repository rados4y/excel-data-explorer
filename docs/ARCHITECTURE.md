# Architecture
One Tauri 2 process owns the Rust engine, tray and React WebView. There is no HTTP application server, cloud dependency, Python backend or external database. Python is used only to generate deterministic example OOXML files. Vite serves frontend assets during development only.

Native Windows dependencies are gated behind the `desktop` Cargo feature. The same core runs without a WebView in Linux tests, the diagnostic JSON-lines CLI and the benchmark executable. Production IPC is a Serde-tagged `Request` enum dispatched on Tauri's blocking pool. TypeScript's command map mirrors request and response types. Requests expose no arbitrary SQL, scripts, shell commands or file-open paths.

`config.rs` validates profiles before persistence. `excel.rs` reads immutable Calamine snapshots and emits one normalized row at a time. `indexing.rs` writes isolated SQLite staging projections and documents. `importer.rs` activates one physical workbook transactionally. `engine.rs` owns typed cached query, relationship, document and settings services. `sync.rs` owns change detection, stable copies, the bounded coalescing queue and its single background worker. `desktop.rs` owns native OS integration and the secure document opener. `lifecycle.rs` isolates launch/close policy for unit tests.

SQLite WAL is the interactive read model. Query operations use independent short-lived connections; count+page uses one read transaction. Parsing and filesystem I/O hold no main-database write lock. A writer gate coordinates configuration activation and workbook activation; the SQLite transaction is the atomicity boundary for records, typed fields, FTS, document links, relation edges, source fingerprint/generation and successful import history. Settings/document status use independent short SQLite writes.

The worker imports one workbook at a time; manual/notification/periodic requests coalesce by workspace and workbook. Multiple mapped worksheets share one snapshot and activation. Normalized rows/projections are staged on disk rather than accumulated in another in-memory dataset. Calamine itself materializes worksheet ranges, which is the remaining large-workbook memory limit. Large activation and graph-rebuild transactions can be long; readers retain a valid WAL snapshot, and their latency is measured during forced imports.

The UI uses TanStack Table and Virtual over bounded 100-record backend pages. Query effects discard superseded responses. Views persist selection, detail visibility, filters, single-column sort, page offset and column widths in SQLite. Tauri's window-state plugin persists geometry while intentionally excluding visibility. Cached UI is available before background synchronization. Sync notifications trigger authoritative status queries and generation-based invalidation; focus and a 10-second UI refresh recover missed events.

The test-only Playwright bridge maps browser IPC to a real long-lived Rust CLI process over stdin/stdout. Its event shell is stubbed; records, filters, mappings, relations, PDFs and persistence all use the actual engine/SQLite. It starts no backend HTTP service and is absent from production code. Native Windows lifecycle and default application launching require the separate Windows acceptance checks.

`spaces.rs` implements explicit workbook inspection, configuration-free space creation and page/mapping mutations. Inspection uses a stable private snapshot and is the onboarding operation that reads Excel; page browsing stays in SQLite. Managed profiles use the existing validated configuration transaction with an `app://spaces/<id>` marker, so an empty installation needs no external YAML or bundled demo. Workbook ingestion still groups all configured worksheets from one physical file atomically. Presentation configuration has a separate ingestion hash, permitting offline page/view/visibility edits without forcing a workbook import.

Pages retain a source identity, visible columns, default sort and optional authoritative fixed filters. The backend validates page requests and applies their source/filter scope; hidden navigation pages are not directly queryable by page ID. Visibility is a presentation preference, not a local data-access boundary. Legacy main/detail YAML views retain their initial main page and relational behavior.

`nested.rs` validates per-page nested view edits and dispatches bounded child queries through the existing SQLite relationship service. Relationship definitions optionally scope a pair of source IDs, enabling generic worksheets with separate namespaces to link without changing record identity. `RelatedViewsDialog` edits those definitions in-app; `NestedRecords` renders each child page with its filters/columns/sort. Detail navigation carries the child page ID through each level and restores its parent when navigating back. Link edits rebuild cached edges in the same activation transaction and never inspect Excel.
